- **No scripts.** Do not write Playwright/CDP/JS/Python that fills JSON or clicks for you. Drive the browser by hand, one cell at a time, in checklist order.
- **Pace is graded:** `fetchTime` of each cell must be **≥ 20 s** after the previous cell (and after run start). Faster = FAIL.

- **Screenshot after the action:** it must show the result the cell measures (error message, selector, landing page, token error). A pre-action page is FAIL in review.

Include **every** numeric criterion for PASS. Do not use booleans or strings for numeric metrics. D3 BLOCKED must include its criteria too. Other BLOCKED requires a concrete dependency reason. Screenshot dimensions must exactly match viewport. FAIL requires reason and screenshot. Unique PNG bytes and SHA256 per cell. `fetchTime` and runId must match this completed run. Browser query strings are deliberately excluded from route records. No tokens in records.

Keyboard 7 checks = Tab, Shift+Tab, Enter, skip link, visible focus, unobscured focus, reduced motion. Feedback 7 checks = labels, autocomplete, described errors, aria-invalid, alert, status, first-error focus. UI cells also verify single request while loading. Staff switch screens need seeded sessions; activation/reset/invite need real private token state. Provision separate accounts/tokens for each viewport when success consumes a token or changes credentials; never reuse a consumed success fixture as a fresh success case. For UI controls not present on a route, verify their applicable semantic equivalents (for example activation resend status and labelled context selectors), record observed failures, and do not invent checks.

Cross-site probe: open provided attacker page from **3001**, targeting **3000**. Simple text/plain POST avoids a preflight-only test. CORS blocks reading the response in script; inspect the actual POST status, response code **FORBIDDEN**, message **“Yêu cầu không hợp lệ”**, and zero Set-Cookie in DevTools. The different ports are cross-origin (browser fetch metadata can say same-site); they must not qualify as same-origin. Login requires application/json plus Sec-Fetch-Site same-origin or Origin equal to NEXT_PUBLIC_SITE_URL. Our text/plain POST is intentionally untrusted and must receive **403**, not 400. A JSON fetch would trigger OPTIONS first, so an OPTIONS-only failure is insufficient. No response cookie values may be recorded. Credential-free payload tests origin rejection before validation (403 rather than 400).
